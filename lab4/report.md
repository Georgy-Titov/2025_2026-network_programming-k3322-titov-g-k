#### Структура программы P4

Программа на P4 состоит из нескольких основных этапов обработки:

* Parser — извлечение заголовков из входящего пакета;
* VerifyChecksum — проверка контрольных сумм;
* Ingress — основная логика обработки и маршрутизации;
* Egress — дополнительная обработка перед отправкой;
* ComputeChecksum — пересчёт контрольных сумм;
* Deparser — формирование выходного пакета.

#### Описание используемых заголовков

Для работы программы были определены структуры Ethernet и IPv4.

Ethernet-заголовок содержит:

* MAC-адрес назначения;
* MAC-адрес источника;
* поле EtherType.

```
header ethernet_t {
    macAddr_t dstAddr;
    macAddr_t srcAddr;
    bit<16> etherType; # Поле EtherType используется для определения типа инкапсулированного протокола. IPv4-заголовок содержит стандартный набор полей IPv4:
}
```
```
header ipv4_t {
    ...
    ip4Addr_t srcAddr;
    ip4Addr_t dstAddr; # Особый интерес для маршрутизации представляет поле dstAddr, по которому принимается решение о дальнейшей пересылке пакета.
}
```

#### Реализация парсера

Первым этапом обработки является извлечение заголовков из входящего пакета.

```
state start {
    packet.extract(hdr.ethernet);

    transition select(hdr.ethernet.etherType) {
        TYPE_IPV4: parse_ipv4;
        default: accept;
    }
}
```

Сначала коммутатор извлекает Ethernet-заголовок. Далее анализируется поле EtherType.

Если значение соответствует IPv4 (0x0800), выполняется переход к состоянию parse_ipv4.

```
state parse_ipv4 {
    packet.extract(hdr.ipv4);
    transition accept;
}
```

На этом этапе из пакета извлекается IPv4-заголовок, после чего управление передаётся в блок Ingress. Таким образом, после завершения работы парсера коммутатор получает доступ ко всем полям Ethernet и IPv4, необходимым для дальнейшей обработки.

#### Реализация логики маршрутизации

Основная логика программы реализована в блоке `MyIngress`.

Для обработки пакетов определены два действия.

Первое действие используется для удаления пакетов:

```
action drop() {
    mark_to_drop(standard_metadata);
}
```

Если для пакета не найден маршрут, он будет отброшен.

Второе действие отвечает за пересылку IPv4-пакетов:

```
action ipv4_forward(macAddr_t dstAddr,
                    egressSpec_t port)
{
    standard_metadata.egress_spec = port;

    hdr.ethernet.dstAddr = dstAddr;

    hdr.ipv4.ttl = hdr.ipv4.ttl - 1;
}
```

Во время выполнения действия происходит:

* Выбор выходного порта (egress_spec).
* Замена MAC-адреса назначения.
* Уменьшение значения TTL на единицу.

Уменьшение TTL является обязательной операцией для любого маршрутизатора, поскольку предотвращает бесконечную циркуляцию пакетов в сети.

#### Таблица маршрутизации

Для принятия решения о пересылке используется таблица `ipv4_lpm`.

```
table ipv4_lpm {
    key = {
        hdr.ipv4.dstAddr : lpm;
    }

    actions = {
        ipv4_forward;
        drop;
        NoAction;
    }

    size = 1024;
    default_action = drop();
}
```

В качестве ключа используется поле: `hdr.ipv4.dstAddr`

Тип поиска: `lpm` - означает Longest Prefix Match (поиск по самому длинному совпадающему префиксу).

Данный механизм является стандартным способом маршрутизации IP-пакетов и применяется в большинстве современных маршрутизаторов. Если для адреса найден маршрут, выполняется действие ipv4_forward. Если совпадение отсутствует, применяется действие по умолчанию drop().

#### Применение таблицы

Вызов таблицы выполняется в блоке `apply`.

```
apply {
    if (hdr.ipv4.isValid()) {
        ipv4_lpm.apply();
    }
}
```

#### Формирование выходного пакета

После завершения обработки пакет должен быть снова преобразован в последовательность байтов.

Для этого используется блок `Deparser`.

```
control MyDeparser(packet_out packet,
                   in headers hdr)
{
    apply {
        packet.emit(hdr.ethernet);
        packet.emit(hdr.ipv4);
    }
}
```

Сначала в пакет записывается Ethernet-заголовок, затем IPv4-заголовок. После этого пакет передаётся на выбранный выходной интерфейс.

### Implementing Basic Tunneling

<img width="1369" height="640" alt="image" src="https://github.com/user-attachments/assets/8b23c0c0-3ce3-4a56-a1fa-8e8e54ed6146" />

> Во втором задании была реализована поддержка пользовательского туннельного заголовка, позволяющего выполнять пересылку пакетов не по IP-адресу назначения, а по специальному идентификатору внутри туннеля.

#### Добавление нового заголовка

Для реализации туннелирования в программу был добавлен новый заголовок:

```
header myTunnel_t {
    bit<16> proto_id;
    bit<16> dst_id;
}
```

Поле `proto_id` определяет тип вложенного протокола, а поле `dst_id` используется для выбора конечного получателя внутри туннеля.

> Также был добавлен собственный EtherType: const bit<16> TYPE_MYTUNNEL = 0x1212;

#### Изменение парсера

```
   state parse_ethernet {
        packet.extract(hdr.ethernet);

        transition select(hdr.ethernet.etherType) {
            TYPE_MYTUNNEL : parse_tunnel;
            TYPE_IPV4 : parse_ipv4;
            default : accept;
        }
    }

    state parse_tunnel {
        packet.extract(hdr.myTunnel);

        transition select(hdr.myTunnel.proto_id) {
            TYPE_IPV4 : parse_ipv4;
            default : accept;
        }
    }

```

Парсер был расширен поддержкой нового типа пакетов. Теперь после разбора Ethernet-заголовка выполняется проверка поля `etherType`. Если обнаруживается значение `TYPE_MYTUNNEL`, извлекается заголовок `myTunnel`, после чего выполняется дальнейший разбор вложенного IPv4-пакета. Таким образом, парсер способен обрабатывать как обычные IPv4-пакеты, так и пакеты, передаваемые через пользовательский туннель.

#### Реализация обработки туннельных пакетов

```
table myTunnel_exact {
    key = {
        hdr.myTunnel.dst_id : exact;
    }

    actions = {
        myTunnel_forward;
        drop;
        NoAction;
    }
}
```

В отличие от стандартной IPv4-маршрутизации, поиск выполняется по полю `dst_id`, содержащемуся в туннельном заголовке.

Для пересылки пакетов используется действие:

```
action myTunnel_forward(egressSpec_t port) {
    standard_metadata.egress_spec = port;
}
```

#### Логика обработки пакетов

В блоке `Ingress` была реализована следующая логика:

```
apply {
    if (hdr.myTunnel.isValid()) {
        myTunnel_exact.apply();
    }

    if (hdr.ipv4.isValid() && !hdr.myTunnel.isValid()) {
        ipv4_lpm.apply();
    }
}
```

Если пакет содержит заголовок `MyTunnel`, пересылка выполняется через таблицу `myTunnel_exact`. Если туннельный заголовок отсутствует, используется обычная IPv4-маршрутизация через таблицу `ipv4_lpm`.

Для этого был разработан собственный заголовок MyTunnel, расширен парсер, добавлена отдельная таблица коммутации и реализован механизм пересылки пакетов по идентификатору туннеля. Таким образом, в ходе работы были получены практические навыки разработки, компиляции и тестирования P4-программ, а также изучены механизмы реализации пользовательских сетевых протоколов и алгоритмов обработки пакетов в программируемых коммутаторах.
