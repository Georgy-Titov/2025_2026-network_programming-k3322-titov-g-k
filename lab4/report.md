## Описание

В данной лабораторной работе вы познакомитесь на практике с языком программирования P4, разработанный компанией Barefoot (ныне Intel) для организации процесса обработки сетевого трафика на скорости чипа. Barefoot разработал несколько FPGA чипов для обработки трафика которые были встроенны в некоторые модели коммутаторов Arista и Brocade.

## Цель работы

Изучить синтаксис языка программирования P4 и выполнить 2 задания обучающих задания от Open network foundation для ознакомления на практике с P4.

## Задание

Ход работы:

1. склонировать репозиторий p4lang/tutorials;
2. уcтановить Vagrant и VirtualBox;

## Выполнение работы

### Устанвока Vagrant

Для подготовки среды разработки были установлены VirtualBox и Vagrant. VirtualBox использовался в качестве гипервизора для запуска виртуальной машины с операционной системой Ubuntu, а Vagrant — для автоматизации процесса её развертывания и настройки.

После установки необходимого программного обеспечения был клонирован репозиторий p4lang/tutorials, содержащий готовую конфигурацию виртуальной машины и набор учебных заданий по языку программирования P4:

```
git clone https://github.com/p4lang/tutorials.git
```

Далее был выполнен переход в каталог с конфигурацией виртуальной машины:

```
cd tutorials/vm-ubuntu-20.04
```

Запуск виртуальной машины осуществлялся командой:

```
vagrant up
```

На данном этапе возникла проблема, связанная с ограничением доступа к необходимому образу Ubuntu из Российской Федерации. Для её решения базовый образ был загружен вручную, после чего процесс развертывания был успешно продолжен.

При первом запуске Vagrant автоматически создавал виртуальную машину в VirtualBox и выполнял её первоначальную настройку (provisioning), включая установку всех необходимых компонентов для работы с P4. В среду были установлены Mininet, программный коммутатор BMv2, компилятор p4c, библиотеки P4Runtime и сопутствующие инструменты.

После завершения настройки подключение к виртуальной машине выполнялось с помощью команды (Не обязательно подкючаться через консоль, VM поднимется сама и можно будет работать через GUI):

```
vagrant ssh  # если хотии работать через консоль
```

## Вывод

В ходе выполнения лабораторной работы были изучены возможности интеграции системы управления сетевой инфраструктурой NetBox с системой автоматизации Ansible. Был развернут и настроен сервер NetBox, включающий PostgreSQL в качестве базы данных и Redis для обеспечения работы фоновых задач и кэширования. Для доступа к API был создан и настроен токен версии v2.

В рамках работы были разработаны и протестированы три Ansible-плейбука. Первый плейбук выполнял экспорт данных из NetBox и формировал локальный JSON-файл с информацией о площадках, устройствах, интерфейсах и IP-адресах. Второй плейбук осуществлял сбор уникального идентификатора MikroTik CHR (system-id) и автоматически записывал его в поле серийного номера соответствующего устройства в NetBox. Третий плейбук демонстрировал использование NetBox в качестве единого источника достоверных данных (Source of Truth): из NetBox автоматически получались параметры устройств, после чего выполнялась настройка маршрутизаторов, включая изменение имени устройства и назначение IP-адреса на интерфейс WireGuard.

В процессе выполнения работы были рассмотрены вопросы взаимодействия Ansible с API NetBox, использования коллекции netbox.netbox, работы с динамическими данными инвентаря, а также особенности автоматизации настройки устройств MikroTik RouterOS через SSH.

Полученные результаты подтвердили возможность централизованного хранения информации о сетевой инфраструктуре в NetBox и её последующего использования для автоматизированного управления сетевыми устройствами. Использование связки NetBox и Ansible позволяет существенно сократить объём ручных операций, повысить актуальность конфигурационных данных и снизить вероятность ошибок при администрировании сети.
